## 1. Решения, нужные до EPIC 1

### Р1. Где хранить новые сущности: импорты, версии, предзаказы, пользователей, аудит

| | A. SQLite (расширить `core/storage.py`) | B. PostgreSQL сразу |
|---|---|---|
| Инфраструктура | нет, бэкап — копия файла | отдельный контейнер, бэкапы, Alembic |
| Существующие 317 тестов | не трогаются | фикстуры и `Storage` переписываются |
| Конкурентная запись (виджет + Telegram + админка) | выдерживает при WAL и `busy_timeout`; один писатель в момент | без ограничений |
| Шифрование контактов (`pgcrypto`) | нет | есть |
| Время до первой пользы | 0 | +3–5 дней |

**Рекомендация: A** до EPIC 4 включительно. Новые таблицы — за
репозиторными интерфейсами, миграции — версионированные SQL-файлы и таблица
`schema_migrations`. К варианту B вернуться перед EPIC 5 (админка с
несколькими пользователями) или перед продом с реальными ПДн. Интерфейсы при
переезде не меняются, так что ошибка здесь стоит дёшево.

### Р2. Что такое «утверждённый каталог» для бота

| | A. Снимок-файл версии + указатель | B. Бот читает каталог из таблиц |
|---|---|---|
| Поиск, карточки, агент, 317 тестов | без изменений: `CatalogIndex` строится из снимка, как сейчас | переписываются под БД |
| Откат | новая версия — копия прежней (D11, H) | транзакция по версиям |
| RAW и APPROVED раздельно | физически: таблицы импорта и файлы снимков | логически, статусами |

**Рекомендация: A.** Импорт, diff и ручное сопоставление живут в таблицах —
они нужны админке. После утверждения собирается
`data/kb/versions/<версия>/products.jsonl`, а указатель `current` переключается
атомарно. Каталог обновляется без перезапуска процессов: при смене указателя
процесс собирает и подменяет единое состояние каталога (§6.8, D11).

### Р3. Tilda — нужен ответ, не угадываем

По данным проекта сайт vdm.ru работает на **1С-Битрикс**. Это видно по разметке
карточек, по ID Битрикса во втором листе выгрузки и по заглушке `Bitrix24Sink`.
Tilda не упоминается ни в коде, ни в документах, ни в переписке с заказчиком.

Пока ответа нет, предлагаю ввести интерфейсы и реализовать их на том, что уже
работает:

- `CatalogSource` → `OneCXlsxSource` (обёртка над `ingest/`);
- `CardSource` → `BitrixSiteCardSource` (обёртка над `media/`);
- `CRMAdapter` / `NotificationChannel` → текущие приёмники `orders/sinks.py`.

`TildaCatalogSource` и `TildaCRMAdapter` появятся, когда станет ясно, что именно
находится на Tilda и есть ли API или экспорт.

### Р4. Админ-панель

| | A. Серверный рендер: FastAPI + Jinja2 + htmx | B. SPA (React/Vite) |
|---|---|---|
| Сборка | нет | npm, сборка, второй стек |
| Экраны ТЗ (таблицы, фильтры, шаги импорта, ручное сопоставление) | формы и таблицы, хватает | богаче, но избыточно |
| Сопровождение соло | один язык | два |

**Рекомендация: A.** Отдельное приложение `src/admin/` и отдельный сервис

виджета не даём, авторизация своя.

### Р5. База знаний в Obsidian

- **В vault** уходят редактируемые тексты: справка из `norms/reference.py`,
  утверждения из `НОРМАТИВКА_НА_ПОДТВЕРЖДЕНИЕ.md`, правила аудитории, FAQ,
  пояснения.
- **Структурированными данными остаются** справочник пунктов
  (`norm_items.json`) и маппинги пункт → товар. В vault они попадают только
  ссылкой с frontmatter, рукописных маппингов нет.
- **Импортёр** читает Markdown + YAML frontmatter, проверяет и индексирует
  файлы для `explain_norm` и `find_norm_item`. Obsidian.exe на сервере не нужен.

### Р6. Word и PDF

- **Excel** уже пишется без зависимостей (`orders/sinks.py:_write_xlsx`) —
  расширяем.
- **Word** — рекомендация `python-docx` + шаблон `.docx`: ручная сборка
  docx-zip хрупкая.
- **PDF на выходе** — отложить: конвертация docx → pdf требует LibreOffice. ТЗ
  допускает это («где возможно»).
- **PDF на входе** — `pypdf` уже в зависимостях. Скан без текстового слоя →
  `REVIEW_REQUIRED`, OCR не делаем.

### Р7. Загруженные файлы

Складываются в `data/uploads/<sha256[:2]>/<sha256>.<ext>`, метаданные — в
таблице `files` (поля из ТЗ, п. 62). `data/uploads/` добавить в `.gitignore`.
Контрольная сумма служит ключом идемпотентности (п. 63).
