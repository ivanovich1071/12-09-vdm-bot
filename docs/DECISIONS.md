# Решения по вопросам аудита

Приняты заказчиком разработки 12.09.2026 по итогам [AUDIT.md](AUDIT.md). Имеют
приоритет над вариантами в [IMPLEMENTATION_PLAN.md](IMPLEMENTATION_PLAN.md), где
они расходятся.

---

## D1. Tilda — не используется

- vdm.ru работает на 1С-Битрикс. В коде, архитектуре и материалах Tilda не
  обнаружена.
- `TildaAdapter` не реализуется. Предположения о Tilda API и Tilda CRM не
  делаются. Tilda не является источником истины и не блокирует v2.
- Создаются только интерфейсы `CatalogSource`, `CardSource`, `CRMAdapter`,
  `NotificationChannel`.
- Реализации текущего этапа: `OneCSource` (цены, наличие, коды),
  `BitrixSiteCardSource` (карточки, описания, фото), адаптеры поверх
  существующих приёмников заказов.
- Статус Tilda: **UNKNOWN / NOT IMPLEMENTED**. Если заказчик предоставит данные
  (что на Tilda, URL, API, доступы, формат, сценарий CRM), это оформляется
  отдельной задачей интеграции.

## D2. Промпты v2 — ещё не переданы

- Найденные материалы — промпт бота «Иван», промпт-оценщик сделок, расшифровка
  вебинара — используются только как справочные. Финальными промптами v2 они
  не считаются.
- Разработка их не ждёт. Слой промптов изолирован: тексты лежат в
  `src/agent/prompts/{common,consultant,salesman,router,guard}.md` и читаются
  загрузчиком. В Python содержание промптов не зашивается.
- Финальные промпты v2 заменят файлы без изменения бизнес-логики.

## D4. База данных — SQLite до EPIC 4 за репозиториями

- EPIC 0–4 работают на SQLite. PostgreSQL рассматривается перед EPIC 5 или
  перед многопользовательским продом.
- Обязательное условие: `Application Service → Repository Interface → SQLite
  Repository`. Прямые `sqlite3.connect` / `cursor.execute` в бизнес-модулях
  запрещены. Переход на PostgreSQL — это замена реализации репозитория, логика
  при этом не меняется.

## D5. Бот читает только утверждённый каталог

- Конвейер: RAW IMPORT → VALIDATION → NORMALIZATION → MATCHING → DIFF →
  ADMIN REVIEW → APPROVAL → APPROVED SNAPSHOT → CatalogIndex → BOT.
- Сырой импорт не меняет данные бота. Утверждение создаёт
  `data/kb/versions/<версия>/products.jsonl`, а `data/kb/current` переключается
  атомарно. После утверждения `CatalogIndex` обновляется без перезапуска
  процессов, минимально инвазивно.

## D6. EPIC 0.5 — только R1 и регрессионные тесты

- Исправить R1 минимально, виджет не переписывать. Добавить регрессионные
  тесты, прогнать весь набор и ruff, закоммитить, **остановиться**.
- EPIC 1 не начинать без отдельной команды.

## D7. Уточнения к модели v2 (из того же ответа)

- **`/start`** сбрасывает текущую задачу, этап и подбор. Историю, прежние
  заказы, документы и аудит не трогает. Сейчас `/start` очищает и корзину —
  это меняется только после отдельного теста и без удаления исторических данных.
- **Task profile** расширяет существующий `DialogProfile`. Вторая параллельная
  система состояния не создаётся, поля без необходимости не добавляются.
- **Порядок работы в каждом EPIC:** ANALYZE → IMPLEMENT → TEST → REGRESSION →
  RUFF → DOCUMENT → COMMIT → STOP. Одним проходом всё сразу не делается.
- **Заказ клиента на входе:** сначала Excel и CSV. Word и PDF — по реальным
  образцам заказчика.
- **Таблицы БД** создаются только те, что нужны конкретному EPIC.
