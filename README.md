# 12-09-vdm-bot

**AI-система подготовки и проверки закупки образовательного оборудования** для
**vdm.ru** (ЭЛТИ-КУДИЦ): оборудование и комплекты для детских садов и школ.

Вторая версия рабочего бота-магазина `26-08-vdm-bot`. Существующий бот
сохраняется и расширяется, а не переписывается.

- Каналы: **Telegram**, **виджет-консультант на сайт**; далее Telegram Mini App
  и **MAX** — по готовности токена.
- Модели: **Cloud.ru Foundation Models** (`deepseek-ai/DeepSeek-V4-Flash`),
  запасной провайдер — OpenRouter.
- Развёртывание: **Cloud.ru**.
- Репозиторий **приватный**: коммерческие данные, интеграции, конфигурации.

## Куда идёт v2

- **Новый подбор:** «оснастить кабинет химии в школе по 838» → норматив →
  товары → первая спецификация с актуальными ценами → корзина → предзаказ →
  менеджер.
- **Проверка готового заказа:** загруженный Excel → сопоставление с каталогом →
  цена, наличие, норматив → отчёт о расхождениях → предзаказ → менеджер.
- **Импорт 1С с утверждением:** сравнение выгрузки с каталогом, ручная проверка
  сомнительного, версии каталога и откат. Бот работает только с утверждённой
  версией.
- **Web Admin** для менеджера, база знаний в Markdown (Obsidian), документы
  Excel/Word.

Цена, наличие, артикул и нормативное соответствие берутся **только из данных**:
1С, карточек сайта и нормативной базы. Модель не является источником истины.
Итоги и статусы считает бэкенд.

ТЗ — [docs/TZ_V2.md](docs/TZ_V2.md), статус и план —
[ДОРОЖНАЯ_КАРТА.md](ДОРОЖНАЯ_КАРТА.md).

## Что бот умеет уже сейчас

- Консультирует по всему ассортименту на основе выгрузки 1С заказчика.
- **Подбирает по нормативным перечням:** понимает «2.20.63», «п. 2.1.14», «2.4»
  и запросы вида «кабинет физики по приказу 838». Основание берётся из данных.
  Приказ 838 — только для школ, 1057 — только для садов.
- **Объясняет сами документы** («что значит приказ 838») даже при недоступной
  модели.
- **Два агента:** консультант объясняет, продавец выясняет задачу, подбирает и
  отрабатывает возражения. Карточки с кнопками появляются, когда задача ясна и
  возражение снято.
- **Проверяет ответ модели:** сумма или пункт приказа, которых не было в
  результатах инструментов, до пользователя не доходят.
- **Держит контекст разговора:** учреждение, кабинет, возраст, срок и бюджет не
  переспрашиваются.
- Ведёт корзину и доводит до заявки менеджеру. **Онлайн-оплаты нет.**
- **Соблюдает ФЗ-152:** согласие до сбора контактов, маскирование ПДн перед
  отправкой в модель, обезличенная переписка не дольше 30 дней, экспорт и
  удаление данных.

## Быстрый старт

```bash
python -m venv .venv
.venv\Scripts\pip install -e ".[dev]"
cp .env.example .env

# собрать базу знаний из выгрузки 1С
python run.py ingest --source data/raw/<выгрузка>.xlsx

# реестр заказчика «пункт приказа 1057 → код 1С», затем пересборка
python run.py norms --source <реестр>.pdf
python run.py ingest --source data/raw/<выгрузка>.xlsx

# проверить поиск из консоли
python run.py search "мячи для спортивного зала в наличии до 2000 руб"

# виджет и демо-страница: http://localhost:8000/demo
python run.py widget

# Telegram-бот (нужен TELEGRAM_TOKEN)
python run.py telegram

# тесты и линтер
python -m pytest -q
ruff check src tests run.py
```

Без ключа Cloud.ru бот работает: отвечает поиском по каталогу, корзина и заказ
полностью рабочие. Ключ включает диалоговый режим.

> ⚠️ `tests/test_web.py` при импорте `web.app` читает настоящий `data/kb` и
> создаёт `data/vdm.sqlite3` (docs/AUDIT.md, R5). Без собранной базы знаний этот
> файл тестов не соберётся.

## Устройство

```text
Telegram · виджет · (Mini App, MAX)     адаптеры, без бизнес-логики
            ↓
       core/  ядро диалога              корзина · заказ · согласия · примитивы ответа
            ↓
agent · catalog · norms · orders · privacy · media
            ↓
  выгрузка 1С → products.jsonl → индекс каталога в памяти
```

| Каталог | Что внутри |
|---|---|
| `src/core/` | Диалог, профиль задачи, корзина, заказ, хранилище SQLite, примитивы ответа |
| `src/agent/` | Консультант и продавец, маршрутизатор, провайдеры моделей, инструменты, проверка ответа, промпты |
| `src/catalog/` | Контракт товара, размещение (учреждение, кабинет, возраст), запрос, репозиторий и сервис каталога; поиск: точный по пункту перечня, BM25, триграммы |
| `src/ingest/` | Разбор выгрузки 1С и реестра приказа 1057, дерево каталога, очистка описаний |
| `src/norms/` | Приказы, пункты перечней, привязка товаров, справка по документам |
| `src/orders/` | Приёмники заказа: файл, Excel, Google Sheets, заглушка CRM |
| `src/media/` | Фото и характеристики со страниц сайта, кэш, запись в базу знаний |
| `src/privacy/` | Маскирование ПДн, согласие |
| `src/adapters/`, `src/web/` | Telegram; веб-виджет и HTTP |
| `src/observability/` | Журнал диалогов |

Планируемые модули v2 (`catalog_import/`, `procurement/`, `order_import/`,
`preorder/`, `documents/`, `knowledge/`, `admin/`) появляются по EPIC — см.
[docs/IMPLEMENTATION_PLAN.md](docs/IMPLEMENTATION_PLAN.md).

## Статус

- **v1 работает:** загрузка выгрузки, нормативный слой, поиск, корзина,
  оформление заказа, Telegram-бот, виджет, журнал диалогов, фото, нормативная
  справка, память диалога, ФЗ-152.
- **v2:** EPIC 0 (аудит) и EPIC 0.5 (исправление R1) приняты. EPIC 1 (Catalog
  Domain) реализован и ждёт приёмки: `CatalogService` с фильтрами по
  учреждению, кабинету, цене и наличию, контракт товара с источником у каждой
  группы полей (docs/DECISIONS.md, D8).
- **Тесты:** 415 passed, ruff чистый.

**Ветки:**

- `main` — принятое состояние: снимок baseline `26-08-vdm-bot` @ `6502846` без
  истории (коммит `2fbbefc`), EPIC 0, EPIC 0.5 и документы v2;
- `epic-0/audit`, `epic-0.5/r1-widget-session` — точки завершения EPIC;
- `epic-1/catalog-domain` — текущая работа.

Перед пушем история проверяется gitleaks; разобранные ложные срабатывания
лежат в `.gitleaksignore`.

**Ждём от заказчика:** доступ к CRM, токен MAX, ключ Cloud.ru на его аккаунт,
образцы заказов, реестр «пункт 838 → код 1С».

## Чего нет в репозитории

Намеренно исключены материалы заказчика: выгрузка с ценами, PDF-каталоги,
сохранённые страницы сайта, база знаний, фотографии, SQLite с заказами и
диалогами, полная версия плана и рабочий список вопросов. Также исключены
`.env` и любые ключи. Всё это передаётся вне репозитория.
